# Made for Home – рецепти, финанси, калкулатор и календар (PWA)

Приложение за телефон с Android за рецептите на свещите и аранжировките, приходите и разходите, калкулатор за восък, аромат и боя и календар за съдържание в социалните мрежи. Работи без интернет, пази данните и снимките в паметта на телефона (IndexedDB) и по желание ги синхронизира с вашия OneDrive, като има достъп **само** до собствената си папка там.

## Какво има в папката

| Файл | За какво служи |
|---|---|
| `index.html` | Основната страница на приложението |
| `styles.css` | Външният вид (цветовете и шрифтовете на Made for Home) |
| `app.js` | Навигация, настройки, архив |
| `recipes.js` | Екраните за рецептите |
| `arrangements.js` | Аранжировки и букети |
| `finance.js`, `fin-ui.js`, `cost-ui.js` | Финанси: склад с материали, поръчки, продажби, разходи, себестойност |
| `calc.js`, `calc-ui.js` | Формулите и екранът на калкулатора |
| `calendar.js`, `cal-ui.js` | Календарът: импорт, месец, седмица, постове, задачи |
| `ui.js` | Общи части на екраните |
| `db.js` | Локалното хранилище (IndexedDB) и настройките |
| `image.js` | Компресиране на снимките |
| `sync.js` | Вход с Microsoft (MSAL.js) и синхронизация с OneDrive (Microsoft Graph) |
| `config.js` | **Единственият файл, който редактирате** – тук поставяте Client ID |
| `sw.js` | Service worker – позволява работа без интернет |
| `manifest.webmanifest`, `icons/` | Име, икона и инсталиране на телефона |
| `.nojekyll` | Празен файл, казва на GitHub Pages да публикува файловете както са |

Редът на работа е: **първо GitHub Pages** (за да получите адреса на приложението), **после Microsoft Entra** (там се записва този адрес), **накрая config.js**.

## Ако вече сте качили предишната версия

Ако досега не сте качвали нищо в GitHub, прескочете този раздел и започнете от Част 1.

1. Ако вече сте попълнили Client ID, отворете `config.js` в хранилището си в GitHub и копирайте реда с `clientId`, за да не го загубите.
2. В хранилището натиснете **Add file → Upload files** и плъзнете **всички** файлове от новата папка (и папката `icons`). GitHub ще замени старите със същото име.
3. Отворете отново `config.js` в GitHub и, ако е нужно, поставете обратно вашия Client ID (Част 4).
4. Натиснете **Commit changes** и изчакайте 1–3 минути.
5. На телефона отворете приложението два пъти (при второто отваряне се зарежда новата версия). Данните ви остават – те са на телефона и в OneDrive, не в GitHub.

Регистрацията в Microsoft Entra не се прави наново: адресът и разрешението са същите.

## Част 1. Качване в GitHub Pages

Направете тази част от компютър – качването на папки от телефон е неудобно.

1. Отидете на **https://github.com** и натиснете **Sign up**. Създайте безплатен акаунт (имейл, парола, потребителско име). Потребителското име ще е част от адреса, например `svesti-maria`.
2. След вход натиснете **+** горе вдясно → **New repository**.
3. Попълнете:
   - **Repository name:** `svesti`
   - изберете **Public** (безплатният GitHub Pages изисква публично хранилище; публичен е само кодът, не вашите данни);
   - **не** слагайте отметка на „Add a README file“.
   - Натиснете **Create repository**.
4. На следващия екран натиснете линка **uploading an existing file**.
5. Разархивирайте свалената папка на компютъра. Отворете я, маркирайте **всичко вътре** (Ctrl+A) и го плъзнете в прозореца на GitHub. Папката `icons` трябва да се качи като папка.
   - Файлът `.nojekyll` е скрит в Windows. Ако не се качи, не е проблем – приложението работи и без него.
6. Долу натиснете зеления бутон **Commit changes** и изчакайте качването.
7. Отворете **Settings** (горе в хранилището) → от лявото меню **Pages**.
8. В **Build and deployment** → **Source** изберете **Deploy from a branch**. В **Branch** изберете **main** и папка **/ (root)** → **Save**.
9. Изчакайте 1–3 минути и презаредете страницата. Горе ще се появи адресът, например:
   `https://svesti-maria.github.io/svesti/`
10. Запишете си този адрес **точно**, с наклонената черта в края. Трябва ви в Част 3.
11. Отворете адреса. Приложението вече работи – картите и калкулаторът са готови, липсва само входът с Microsoft.

## Част 2. Проверка дали можете да регистрирате приложение

Microsoft вече не позволява регистриране на приложения с личен акаунт „извън директория“. Затова:

1. Отворете **https://entra.microsoft.com** и влезте с вашия Microsoft акаунт (Outlook/Hotmail/Live – същия, с който ползвате OneDrive).
2. Ако влезете нормално и в менюто виждате **Entra ID → App registrations**, прескочете към Част 3.
3. Ако видите съобщение, че създаването на приложения извън директория е спряно, или грешка, че акаунтът не съществува в тенант „Microsoft Services“:
   - отидете на **https://azure.microsoft.com/free** и натиснете **Start free / Try Azure for free**;
   - влезте със същия Microsoft акаунт и следвайте стъпките (телефон и банкова карта за проверка на самоличността);
   - така се създава безплатна „директория“ (Default Directory). Регистрацията на приложение и входът в него не се таксуват;
   - след това се върнете на **https://entra.microsoft.com**.

## Част 3. Регистрация на приложението в Microsoft Entra

1. В **https://entra.microsoft.com** от лявото меню изберете **Entra ID** → **App registrations** (в по-стари менюта: **Identity → Applications → App registrations**).
2. Натиснете **+ New registration**.
3. Попълнете:
   - **Name:** `Svesti` – с това име ще се появи папката в OneDrive (`Apps/Svesti`, в българския OneDrive `Приложения/Svesti`);
   - **Supported account types:** изберете **Personal Microsoft accounts only** (само лични Microsoft акаунти);
   - **Redirect URI:** от падащото меню изберете **Single-page application (SPA)**, а в полето поставете адреса от Част 1, стъпка 9, например `https://svesti-maria.github.io/svesti/`.
4. Натиснете **Register**.
5. Отваря се страницата **Overview**. Копирайте стойността **Application (client) ID** (дълъг код като `1a2b3c4d-....`). Тя ви трябва в Част 4.
6. Добавяне на разрешението за OneDrive:
   - от лявото меню на приложението изберете **API permissions**;
   - натиснете **+ Add a permission** → **Microsoft Graph** → **Delegated permissions**;
   - в търсачката напишете `AppFolder`, отворете групата **Files** и сложете отметка на **Files.ReadWrite.AppFolder**;
   - натиснете **Add permissions**.
   - Разрешението `User.Read`, добавено автоматично, може да остане – приложението не го използва.
7. Проверка на адреса за връщане: от лявото меню изберете **Authentication**. В секция **Single-page application** трябва да стои вашият адрес. Ако искате да тествате и на компютъра, добавете втори адрес `http://localhost:8000/` с **Add URI** и натиснете **Save**.
8. **Не** създавайте „Client secret“ и **не** добавяйте платформа „Web“. Приложението е изцяло в браузъра и не ползва таен ключ.

## Част 4. Поставяне на Client ID в config.js

1. Отворете хранилището `svesti` в GitHub и натиснете файла **config.js**.
2. Натиснете иконата с молив (**Edit this file**).
3. Намерете реда:
   ```js
   clientId: "ПОСТАВЕТЕ-ТУК-CLIENT-ID",
   ```
   и заменете текста между кавичките с вашия Application (client) ID:
   ```js
   clientId: "1a2b3c4d-1111-2222-3333-444455556666",
   ```
   Кавичките и запетаята в края остават.
4. Ако в Част 3 сте избрали друг вид акаунти (например и служебни), сменете и реда `authority` – `consumers` става `common`.
5. Натиснете **Commit changes** → отново **Commit changes**.
6. Изчакайте 1–3 минути, докато GitHub Pages публикува промяната.

## Част 5. Библиотеката за вход – локално копие (препоръчително)

Приложението зарежда MSAL.js автоматично от jsDelivr и го запазва за работа без интернет. Microsoft препоръчва библиотеката да се сервира заедно с приложението, затова е по-надеждно да я качите и в хранилището:

1. Отворете в браузъра: `https://cdn.jsdelivr.net/npm/@azure/msal-browser@4/lib/msal-browser.min.js` и запазете файла (Ctrl+S) като `msal-browser.min.js`.
2. На компютъра създайте папка `lib` и поставете файла в нея.
3. В GitHub в хранилището натиснете **Add file → Upload files** и плъзнете цялата папка `lib`. **Commit changes**.

Приложението първо търси `lib/msal-browser.min.js` и чак ако го няма, ползва jsDelivr.

## Част 6. Инсталиране на телефона и първи вход

1. На Android отворете **Chrome** и въведете адреса на приложението.
2. Меню **⋮** горе вдясно → **Инсталиране на приложението** (или **Добавяне към началния екран → Инсталиране**).
3. Отворете „Made for Home“ от иконата на началния екран.
4. Отидете в **Настройки** → **Вход с Microsoft**.
5. Изберете акаунта си. Първия път Microsoft ще покаже какво иска приложението – достъп до собствената му папка в OneDrive – натиснете **Приемам / Accept**.
6. Връщате се в приложението, точката горе вдясно става зелена и започва първата синхронизация.
7. По желание натиснете **Защити данните** в Настройки, за да помолите браузъра да не трие данните при недостиг на памет.

Проверка: в OneDrive (на телефона или на onedrive.live.com) отворете **Приложения → Svesti**. Там трябва да има `data.json`, `calendar.json`, `finance.json` и папка `photos`.

## Как работи синхронизацията

- Всичко се записва първо на телефона, затова приложението работи и без интернет.
- Около 4 секунди след всяко записване, при всяко отваряне на приложението и при връщане на интернета то синхронизира автоматично. Бутонът **Синхронизирай сега** прави същото ръчно.
- Снимките се намаляват до 1600 пиксела по дългата страна и се записват като JPEG (обикновено 150–400 KB). Всяка се качва като отделен файл в `photos/`.
- Рецептите са във файла `data.json`, а календарът в `calendar.json`.
- Ако една и съща карта е променяна на две устройства, остава по-новата версия.
- Изтрита карта остава като малък запис „изтрита“, за да се изтрие и на другите устройства. Снимките ѝ в OneDrive се изтриват при следваща синхронизация (след поне 1 ден).
- Точката горе вдясно: зелена – синхронизирано; жълта – синхронизира се; червена – нужен е вход или има грешка; сива – не сте влезли.
- Microsoft периодично иска повторен вход (при уеб приложенията обикновено след около 24 часа или след рестарт). Тогава в Настройки се появява **Влез отново**. Данните на телефона остават достъпни и без вход.

## Календар за съдържание

**Импорт.** Файлът `made-for-home-kalendar-ГОДИНА.json` от другия проект се зарежда от **Настройки → Импорт на календар** (или от празния екран на Календар). Преди да промени нещо, приложението показва колко записа са нови, променени и премахнати. Снимките, текстовете за публикуване и отметките се запазват. Импортирайте винаги целия файл – и при промени, и при нов календар.

**Месец.** Всеки ден показва пост (кръгче), задача (квадратче) и срок или повод (цветна черта). Горе е следващият краен срок. Под календара са предстоящите задачи – отметнете ги, когато са готови.

**Седмица.** Всичко за деня: поводи, срокове, постове, задачи и сторита за отмятане. Горе е текущата фаза на кампанията.

**Фийд.** Предстоящите постове като решетка от снимки, както в профила: първата снимка на всеки пост, датата и иконка за Reel или карусел. Постовете без снимка са с пунктирана рамка и заглавие, за да се вижда какво още трябва да се заснеме. „Като в профила“ обръща реда (най-късният пост горе вляво), а „и последните 30 дни“ добавя и вече минали постове.

**Сторита.** Сторитата за следващите 14 дни, по дни, като вертикални карти със стикера. Всяко правило за стори може да има примерни снимки (отваря се с докосване на картата или от стрелката в изгледа Седмица). Те остават към правилото, показват се при всяко стори от него и се изтриват автоматично няколко дни след последната дата на правилото (същият брой дни като при постовете).

**Пост.** Снимки за вдъхновение, насоки, партида, свързани рецепти, текст за публикуване с бутон „Копирай“ и отметка „Публикуван“.

**Автоматично изтриване.** Снимките на пост, отметнат като публикуван, се изтриват от телефона и от OneDrive няколко дни след датата му (по подразбиране 7, сменя се в Настройки). Текстът остава.

**Ръчни промени.** Пост или задача може да се редактира и в приложението. Ако после импортирате нова версия на календара, стойностите от файла заменят ръчните промени; постовете и задачите, добавени ръчно, не се пипат.

## Изчисления

- Въвеждате колко тежи една свещ само с восък (X). Ароматът е процент от X: аромат = X × %, восък = X − аромат. В Настройки може да смените метода на „процент от восъка“.
- Боята е процент от восъка: боя = восък × доза. Бързите бутони са „Наситен“ (максимумът, по подразбиране 0,4%), „Среден“ и „Светъл“.
- Приложението предупреждава, ако ароматът надвиши максимума на восъка (по подразбиране 10% от восъка) или боята надвиши 0,4%. И двата максимума се сменят в Настройки.
- Ако не знаете X за нов съд: напълнете го с вода, претеглете водата и използвайте „Изчисли теглото от вода“ (вода × 0,86 за соев восък).

## Финанси и цени

**Склад.** Таб **Финанси → Склад** пази всеки материал с цената за единица (грам, мл, брой или метър). Цените идват от импорта на поръчки или се въвеждат ръчно („Платих … € за …“). Материал с отметка „приблизителна цена“ се обновява сам при следваща поръчка на същия материал.

**Импорт на поръчка.** Файлът `made-for-home-poruchki-….json` се зарежда от **Финанси → Импорт на поръчка**. Преди запис приложението показва поръчките и пита за всеки нов материал дали е нов или вече е в склада под друго име. Доставката се разпределя пропорционално в цените. Вече импортирана поръчка (същият код) се пропуска, така че файлът може да се зарежда повторно без дублиране.
- `"mode": "expense"` – разход за месеца на поръчката.
- `"mode": "stock"` – начална наличност: цените влизат в склада, но сумата не се брои за разход.
- Оборудване (`"type": "equipment"`) се брои в разхода, но не влиза в склада и в себестойността на свещите.

**Себестойност на свещ.** В рецептата, в частта **Цена**, изберете восъка, аромата, боята, фитила и съда от склада, плюс етикет, опаковка и др. Грамовете идват от рецептата. За фитил на метър въведете дължината на един фитил в см. Ароматите на мл се смятат 1 мл ≈ 1 g.

**Цена.** Приложението показва материалите, материалите × коефициента (по подразбиране 2, сменя се в Настройки) и вашата закръглена цена с реалния коефициент. Ако реалният коефициент е под зададения, числото е в червено.

**Аранжировки.** В **Рецепти** превключвателят „Свещи | Аранжировки“. Аранжировката се сглобява от свещи от рецептите и материали от склада и се преизчислява сама при промяна на цените. „Копирай“ прави вариант за поръчка по желание. Свещ, отметната „Само за аранжировки“, не се показва в основния списък, а под чипа „За аранжировки“.

**Продажби и разходи.** Продажба: свещ, аранжировка или друго, брой, цена, канал и клиент по желание. Себестойността се записва към датата на продажбата. Разходи без поръчка (куриер, такса за базар, реклама) се добавят ръчно. **Месец** показва приходи, разходи, резултат и кои продукти носят най-много. „Месецът за Excel“ сваля таблица за счетоводителя.

В **Настройки → Архив на файл**:

## Чести проблеми

**AADSTS50011 / „redirect URI … does not match“** – адресът в Entra (Част 3, стъпка 3) не съвпада точно с адреса на приложението. Проверете `https`, името на хранилището и наклонената черта в края. Типът трябва да е **Single-page application**, не „Web“.

**„unauthorized_client“ или „not enabled for consumers“** – в Entra е избран вид акаунти без личните акаунти, или `authority` в `config.js` не съвпада. При „Personal Microsoft accounts only“ трябва да е `consumers`.

**„AADSTS9002326 … Cross-origin token redemption“** – адресът е добавен като „Web“ вместо „Single-page application“. Изтрийте го от Web и го добавете в SPA.

**Входът се върти в кръг** – проверете дали отваряте приложението от точния адрес, записан в Entra, и дали Chrome не блокира бисквитки за `login.live.com`.

**„Грешка при синхронизация: 403“** – липсва разрешението `Files.ReadWrite.AppFolder` (Част 3, стъпка 6). Добавете го, после натиснете **Изход** и влезте отново.

**В Настройки пише „Входът с Microsoft още не е настроен“** – `config.js` още съдържа `ПОСТАВЕТЕ-ТУК-CLIENT-ID` или GitHub още не е публикувал промяната. Изчакайте няколко минути и отворете приложението отново.

**„Библиотеката за вход не се зареди“** – нямате интернет при първото отваряне след инсталиране. Свържете се веднъж; след това библиотеката се пази в кеша. Или направете Част 5.

## Сигурност и поверителност

- Client ID не е таен – той само казва на Microsoft кое приложение иска достъп. Таен ключ няма.
- Публично в GitHub е само кодът. Картите и снимките са само на телефона ви и в папката на приложението във вашия OneDrive.
- С разрешението `Files.ReadWrite.AppFolder` приложението не вижда останалите ви файлове в OneDrive.
- Достъпът може да се оттегли по всяко време от **https://account.live.com/consent/Manage**.

Стойностите от калкулатора са ориентир. Максималният ароматен товар и количеството боя зависят от конкретния восък – проверявайте техническия лист на производителя и правете тест за горене преди продажба.
